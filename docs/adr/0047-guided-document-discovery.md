# ADR-0047: Guided discovery before writing each preparation document

Retired by [ADR-0049](0049-remove-interview-preparation.md). Kept as historical context only.

Amended by [ADR-0048](0048-durable-preparation-worker.md): AI operations now run as durable tasks, and leaving the page does not cancel them.

Accepted 2026-11-26 after the user requested meaningful clarification questions per document and guidance when they do not know how to answer. Amends ADR-0046's single-call generation flow.

Create and save the pack outline first, without generating questions or teaching bodies. The planning provider schema contains only document id, title, purpose, and prerequisiteIds; the transport maps these to documents with questions=[]. Ignore unsolicited question fields in a planning response so malformed guidance cannot prevent the outline from being saved. Prepare 1–3 targeted questions separately when each document opens, using the shared answers available at that time. Existing saved outlines that already contain questions remain readable. Questions gather missing context and learning needs; they are not interview questions or a scored assessment. Ask one at a time and support written answers, explicit uncertainty, skipping, and saving partial progress. Avoid asking for facts already present in the CV, job, projects, or saved answers elsewhere in the pack.

Each question includes practical help, an empty answer structure, and a clearly hypothetical example. The seeker can ask for more guidance in their own words. Help is read-only: generated examples, suggested wording, and unconfirmed drafts never enter the saved answer ledger automatically. Using a blank structure is an explicit user action; saving the edited answer is separate.

Distinguish uncertainty about knowledge from uncertainty about past experience. Knowledge uncertainty should lead to foundations, worked examples, and small practice tasks. Missing project evidence stays unknown or tentative and gets investigation guidance; it must not produce invented accomplishments. Skipping every question is valid and still permits a useful document based on the remaining sources.

Save the complete per-document question set, response statuses, and user text inside the existing versioned pack body. No SQL schema migration is needed. All writes use the expected pack revision and ownership checks. The answer ledger is shared across document generation. Later unanswered question sets can refresh from the current shared context; do not replace a user's draft or resolved responses merely because another document changed.

Writing or rewriting one document validates that replacement before saving and preserves other documents. Reset only that document's readiness and study-day completions that reference it. Saved answer changes advance a context revision: previously written documents show a review notice without automatic regeneration. Sources keep separate fingerprints so source changes remain visible even as individual documents are rewritten.

Existing packs remain readable. They can acquire questions one document at a time without discarding content or progress. Creating a new outline remains an explicit whole-pack replacement. Failed planning, help, or writing must preserve saved material. A write failure after a successful answer save keeps the saved answers available for retry.

Continue the explicit demo/live distinction and the accuracy boundaries from ADR-0046. The AI has no live browsing or code execution, and guidance must not claim verification or assessed mastery.

Live-response hardening: retain application validation, but constrain day/minute values and question kinds in a compact provider schema. Avoid large nested array length bounds that exceed Gemini's schema complexity limits. Give planning sufficient output budget; enlarge the budget on a token-limit retry and supply specific repair instructions for failed contract rules. Log only operation names, safe finish/failure codes, and token counts, never response/source text or credentials. Warn before navigation or reload cancels an active generation request.

Provider limits and schema choices were checked against [Gemini 2.5 Flash model limits](https://ai.google.dev/gemini-api/docs/models/gemini-2.5-flash) and [Google's structured-output documentation](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/capabilities/control-generated-output).

Independent recall, reflection, rehearsal, and rest/preparation activities may have an empty documentIds list. A study session must still have a concrete activity and stay within the time budget; every supplied document reference must exist, and every document must be scheduled somewhere. Requiring a reading link for every activity rejected otherwise valid live-model plans. The provider schema and application validation must agree on that distinction.

A draft outline may contain documents whose questions are not prepared yet. Opening an unwritten document prepares those questions on demand. The write transition still requires a non-empty question set with each response answered, unknown, or skipped. Rejecting the whole draft because a rehearsal/review document deferred its questions prevented otherwise useful plans from being saved.

Plan-generation contract hardening (2026-11-26): document ids match `^[a-z][a-z0-9-]{0,63}$`; they start with a lowercase ASCII letter and contain only lowercase letters, digits, and hyphens, without a filename extension. New discovery output must include a nonempty answerStarter template containing `___` or `[placeholder]` fields, at most 1500 characters. “Blank” means fields awaiting the seeker's own words, never an empty string. Newly generated prompt/whyItMatters are nonempty and at most 1000 characters, guidanceMarkdown at most 6000, and hypotheticalExample at most 2500. Saved older nonempty templates remain readable without a migration.

Prompts, provider schema, and application validation use the same ID and field limits. The documented Schema supports pattern/minLength/maxLength ([Google Schema reference](https://aistudio.google.com/api-reference/caching#Schema), [official SDK schema](https://googleapis.github.io/js-genai/release_docs/interfaces/types.Schema.html)). Keep large nested array bounds in application validation to avoid the earlier schema-complexity failure. Application validation remains authoritative even when a provider accepts schema keywords.

Validation failures carry validator-authored field paths, rule codes, and numeric lengths/limits into safe diagnostics and retry repair instructions. Paths use array indexes and known field names, never generated ids or source text. Include a concrete repair instruction for document_structure and require a nonempty placeholder template on question_guidance retries. Do not store or log generated responses, source text, credentials, or rejected field values. A failed replacement must preserve the previous body, saved answers, progress, and revision.

The original November 26 trace reported question_guidance followed by document_structure, but its responses were not retained. Reproductions establish these failure paths and the contract defects; they cannot identify the original offending fields. Permanent controlled-response tests cover invalid ids, empty/oversized guidance and templates, deferred planning, exact repair paths, privacy, and preservation. Opt-in live tests in PreparationLiveGenerationTests run the actual generator and persistence flow for fictional software-engineering and customer-service profiles through planning, discovery, unknown answer saving, writing, and reload. Supply APPLYVAULT_PREP_LIVE_API_KEY and optionally APPLYVAULT_PREP_LIVE_MODEL securely, then run `dotnet test api/ApplyVault.Api.Tests --filter FullyQualifiedName~PreparationLiveGenerationTests`. These tests incur provider usage and are skipped by default. Passing a small live sample is evidence of integration compatibility, not a reliability guarantee across all inputs.

Verification on 2026-11-26 used the configured Gemini 2.5 Flash provider with fictional sources: a senior software engineer with 40 preparation days produced five outline documents; a customer service adviser with seven days produced four. Both completed deferred discovery (three questions), explicit unknown answer saving, document writing, and persistence reload without a stale-source notice. End-to-end durations were approximately 59 and 61 seconds. These are successful integration samples, not a claim about every input or a review of teaching quality. The original four deterministic repair-feedback tests failed before the change and pass after it; broader preparation and SQL worker regression checks pass separately.
