# ADR-0048: Durable background preparation tasks

Retired by [ADR-0049](0049-remove-interview-preparation.md). Kept as historical context only.

Accepted 2026-11-26 after the user requested generation in a worker so leaving the page does not interrupt preparation. Amends ADR-0046 and ADR-0047's request-bound generation and navigation warning.

Plan creation, whole-pack regeneration, clarification generation, document writing, and additional guidance return HTTP 202 after an owned task is saved in SQL Server. Saves of explicit answers and study progress remain immediate. The API validates ownership and the expected pack revision, and captures the CV, posting, selected projects, saved answers, and requested inputs before acknowledging a task. Workers never receive the seeker's access token. Source payloads are private database state, never fields in task responses or logs.

A separate `ApplyVault.Worker` host runs two concurrent tasks. It depends only on the preparation generator, database, and task processing module; it does not run the web API, mail synchronization, or browser tooling. Both Docker Compose stacks include this service. The API applies the additive `PreparationJobs` migration before the worker starts. SQL Server is the durable queue; Redis is not required.

Acquisition uses a conditional SQL update comparing the candidate lease token and eligibility. Each acquisition gives a fresh token and a 60-second lease; renewal runs every 10 seconds. A crashed worker's lease can be acquired again. A graceful shutdown releases owned work for retry. A cancelled or expired/replaced lease cannot publish. Artifact changes and task completion commit together, outside the provider call's lifetime. A progress-save race reloads and merges persisted progress without calling AI again.

Publication verifies the captured preparation version. Answer/context changes supersede stale work instead of overwriting it. Progress changes and changes to other document bodies do not invalidate a document task; whole-pack replacement intentionally resets progress after version validation. New outline creation keeps the existing per-user/job or general-pack uniqueness constraint. Same-input active tasks coalesce using a unique active key; a different request for that step returns a conflict until the active task is cancelled or completes.

Transient transport errors, provider timeouts, rate limits, and server failures retry with backoff for at most three worker acquisitions (the generator also retains its bounded per-call repair retries). Invalid output and configuration errors fail visibly. Manual retry creates a new owned task from retained inputs, checking current context first. Cancellation is explicit and clears the saved source payload; it is never tied to browser navigation. Completion and supersession also clear source payloads. Terminal task records, including failed source snapshots and guidance, expire after seven days. Deleting a pack clears its task payloads and cancels its active tasks.

The page loads persisted task status on return and polls every four seconds while mounted. Closing the tab stops status polling, not generation. Completed results can be opened explicitly. Document results for the active pack merge without clearing local answer drafts or review notes, advancing the save revision and resetting only the rewritten document’s readiness. Opening a replacement outline or another pack asks before discarding unsaved changes. Answer guidance remains separate from personal facts. Only unsaved answers and study progress trigger the existing leave warning; background generation does not.

Verification includes HTTP ownership/202/cancellation tests, headless browser navigation and unsaved-edit tests, and real SQL Server tests in random scratch databases for competing claims, lease recovery, stale publication, cancellation, safe retry failures, and progress merging. Run the SQL tests with `APPLYVAULT_TEST_SQL_CONNECTION`; they never modify the configured application's database.
