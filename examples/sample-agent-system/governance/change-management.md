# Change Management — Sample Catalog API

| Change type | Process |
|---|---|
| In-bounds code | Delegate → implement → handoff → Architect review |
| Contract proposal | Backend proposes → Architect reviews → user approves if breaking |
| Fleet extension | `/extend-fleet` or regenerate pack after approved spec change |
| Library upgrade | Update Architect library → `/upgrade-architect` |

All material decisions go in `governance/decision-register.yaml`.
